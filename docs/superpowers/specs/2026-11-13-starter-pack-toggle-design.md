# 入门词包：整包加入与移出 — 设计规格

**日期：** 2026-11-13  
**状态：** 已实现，待体验

---

## 1. 背景

iOS 的「导入入门词包」把最多 20 个词直接写入词库，来源记为 `starter:<词表 id>`。词库列表、练习队列和 iCloud 同步都不区分这个来源，所以日常高频里的 time、day、hand 会和用户收藏的词出现在同一轮练习里。

导入之后不能按词包收回。用户只能逐条删除或标成「太简单」。

本规格给每个词表一个整包开关。移出时只删除仍是词包原样的词。练过、改过或后来又收藏过的词留在词库里。

Mac 的网页替换仍使用 `wordRecords`，不进这套名单，本规格不改替换出词。

---

## 2. 入口

设置里的「导入入门词包」改为词表列表，顺序与现有 `StarterPack.lexicons` 相同：日常高频、四级、六级、考研、雅思、托福。

每一行：

- 未加入：按钮「加入」
- 已加入：写明名单上还有几个可移出，按钮「移出」

初次引导保持现在的选择。选一个词表并导入，等于打开该词包。点「暂不导入」则全部保持关闭。

词表文件读不到时，加入失败并提示，名单不变。

---

## 3. 词包原样

一个词仍属于词包，当且仅当它同时满足：

- `source` 为 `starter:<该词表 id>`
- `status` 为 `new`
- `repetitions` 为 0
- `introducedAt` 为 0 或缺省（没点过「看过了」）
- 释义与该词表条目的中文一致
- `usageExample`、`extraExample`、`exampleFromContext` 都没有英文

以下任一发生后，该词不再是词包原样，从名单移除，词条和复习进度保留：

- 练过，包括新词点了「看过了」
- 标过「太简单」，或变成已掌握
- 在详情里改过释义或例句
- 后来从 Safari 点词、系统分享或手机手动添加，再次写入同一个 id

后三类再次写入时，把 `source` 改成该入口的固定值：Safari 点词为 `safari`，系统分享为 `share`，手机手动添加为 `ios`。这样即使释义和例句没变，下次重算也能认出它已经是用户的词。内置词表给空释义补释义（`fillDefinition`）不改 `source`，也不把词移出名单。词包词导入时已有释义，这条补写本来就不会作用在它们身上。

用户自己删掉的词，立刻从名单去掉，并沿用现有墓碑。

---

## 4. 加入

打开词包时：

- 按词表文件顺序，把还不在词库里的词写入，最多 20 个；前面的词已经有了，就继续往后找
- 新写入的词进入该词包名单，`source` 为 `starter:<词表 id>`
- 词库里已经有的词不重复加，也不进名单
- 只要新写入了至少 1 个词，该词包就记为打开，并写下这次操作的时间

词表里已经没有可新增的词时，提示换一个词表，不把词包标成打开。

词包开着时，用户单独删掉的词保持删除。只有关掉再打开，才会把当前不在词库里的词重新加回来。

---

## 5. 移出

移出前确认。名单上还有词时，文案为：「将移出 N 个还没练过的词。已练过或你另外收藏的会保留。」

确认后：

- 删除当前名单上的词，每个词写 `vocab:<id>` 墓碑，时间晚于该词的 `addedAt`
- 这些词若正在本轮练习里，从本轮去掉，与练习中删除当前卡片相同
- 词包标成关闭，名单清空

取消确认则不改词库。

名单已经空了也可以关闭。文案说明没有可移出的词，已练过的会留在词库里。

再次打开只补当前不在词库里的词。上次移出的词作为新词回来。已经脱离、仍在词库里的词不会再加一遍。

---

## 6. 数据

词包状态放在快照 `payload.starterPacks`，不放进 `settings`。设置以 Mac 的 `metaUpdatedAt` 为准，手机写入会被盖掉。

```json
{
  "daily": { "enabled": true, "ids": ["time", "day"], "updatedAt": 1731480000000 }
}
```

- 解码时没有 `starterPacks` 键：尚未归队
- 键存在且值为对象：已经归队。某个词表没有记录，表示该词包关闭
- 新的空快照直接写成 `{}`，不再归队

归队只做一次，发生在第一次读到缺键的快照时：

- 来源是 `starter:<词表 id>` 且仍是第 3 节原样的词，写入该词包的 `ids`
- 这样的词包 `enabled` 为 true，`updatedAt` 用归队时刻
- 练过或改过的旧词留在词库里，不进名单
- 归队后键一直存在

手机负责加入、移出和重算。Mac 不增加词包开关。Safari 再次收藏同一个词时，按第 3 节改 `source`。同步只负责带上 `starterPacks`。

每次读入词库，以及和第 7 节合并完成之后，重算每个已打开词包的 `ids`：只保留仍在词库中、且仍是原样的 id。重算不把词表里的其他词自动加进名单，也不把已关闭的词包重新打开。

---

## 7. 同步

`SnapshotCodec`、`SnapshotMerge` 与扩展里的 `icloud-sync.js` 一起改。`starterPacks` 加入两端的同步键。旧快照缺这个键时，按缺省处理，不把它变成空对象再跳过归队。

同一个词表：

- `enabled` 取 `updatedAt` 较新的一侧。时间相同则取打开的一侧
- 较新一侧是关闭：合并后的 `ids` 为空
- 较新一侧是打开：两侧 `ids` 取并集，再按第 6 节重算

词条本身仍走现有合并。移出留下的墓碑会挡住更早的 `addedAt`。再次打开时新词的 `addedAt` 晚于墓碑，词会回来。

---

## 8. 测试

- 加入会跳过词库已有的 id，只把新词写入名单
- 点「看过了」、评分、标「太简单」、改释义或例句之后，该 id 离开名单，词还在
- Safari、分享、手动添加再次写入同一个 id 后，`source` 不再是词包，重算后离开名单
- 移出只删除当时名单上的词，并写下墓碑；已脱离的词还在
- 取消移出不改快照
- 再打开会补回已删除的词，不会复制仍留在词库里的词
- 词包开着时单独删除的词，在不关闭词包的情况下不会被加回
- 缺 `starterPacks` 的旧快照只把原样词归进打开的词包
- 合并时较新的关闭胜出；一侧已练过的词不会被另一侧的名单加回
- 词表文件缺失时加入失败，名单不变

---

## 9. 不做

- 不把词包收进另一套词库
- 不提供「只暂停练习、不删除」
- 不在词包里逐条勾选
- Mac 不提供词包开关，也不改变网页里的词级替换
